# Rendering friction verification and changes

Source review on 2026-10-15, Linux. Compilation and executable checks belong to the root validation owner; no cargo commands or native UI launch were run by this subagent.

- **4, confirmed.** `frame_render` and `contact_sheet` resolved all `TimeSpec`s through the original project's rate and `at()`, even after `Project::asset_preview` had selected the source's own rate. Picture tools now preserve `seconds`/`us` exactly, and `frame`/timecode use the actual subject's rate. The existing Neptune Video source-frame selector and decoder still choose a frame on the source's frame grid; this is not arbitrary-PTS or a new HDR conversion path. An off-grid clip in-point and matching raw source request are compared as encoded pixels by an end-to-end regression test.
- **5, confirmed.** Previously only full project or raw asset snapshots were drawable. `only_tracks`, `exclude_tracks`, and `solo_clip` now create an owned temporary project projection. Explicitly selected hidden tracks are visible in that projection; the person's track state, editing revision and history stay unchanged. The selected clip retains transform, grade, effects, text styling and animation. Clean-plate asset references, LUTs and fonts remain available. Solo clip sheet/dump defaults start at that clip's start. `frames_export` uses the same projection. Native encoded-video export isolation remains outside this patch: `QueueExport` deliberately captures the authority's project, and accepting arbitrary server-created export snapshots would need a protocol contract. No visibility edits are sent to simulate isolation.
- **6, confirmed.** The cap is 64 Mi pixels (67,108,864), not 67 decimal megapixels. Inline picture requests keep their 48-frame/64-Mi-pixel limits. A new `frames_export` job writes up to 100,000 numbered PNG/JPEG frames through the existing single GPU lane, with a one-frame delivery buffer, source decoder continuity, per-frame encoding/write and cancellation. Default and explicit frame steps use rational frame positions to avoid interval drift. Jobs return a compact filename pattern, count and sampling recipe rather than pictures or a list of every output path. Completed files remain if cancelled or a later frame fails. Existing-output checks run for the entire sequence before any picture is written; writes remain atomic per file. Image, sheet and encoded-video outputs create missing parent directories through root-checked paths, checking links before and after creation; the preexisting check/open race limitation is unchanged.
- **10, contact sheet confirmed.** The schema did not have a `times` field, and deserialization discarded it. Explicit `times` are now consumed in order, including unsnapped microseconds. Supplying both explicit times and even-sampling options is rejected with an actionable message.
- **10, asset prefixes confirmed.** Frame, sheet and dump asset selection now use the shared full UUID/unique hexadecimal-prefix resolver; the root owner implements the common resolver and uses it in other media tools.

Added regression coverage: pure isolation/source-rate and rational dump-range tests in `src/mcp/tools/analysis.rs`; output mkdir/parent-link protection tests in `src/mcp/paths.rs`; `exact_source_times_isolated_layers_and_streaming_dumps_preserve_the_project` in `tests/mcp.rs` covers actual decoded source-frame identity, transform/grade preservation, hidden/excluded tracks, explicit contact times, directory creation, 60-frame streaming and unchanged project revision/visibility. It uses a generated 160x90 60fps H.264 source and a fresh task-owned 30fps project. Native UI acceptance and HDR-source pixel identity have not been established by these tests.

Validation follow-up: root's real end-to-end run passed raw-source/off-grid clip identity and failed the final isolated frame-dump equality. The same-geometry MCP drawer reused `FrameRenderer` across edited snapshots, while the renderer cached decode sizes by clip/asset ID. An earlier scale-1 request therefore left a stale 160x90 decode size for a later scale-0.7 still; the intervening 64px source dump recreated the renderer, so the final isolated dump correctly decoded at the smaller size and produced different resampling pixels. The fix clears project-derived decode sizes/held frames/title/LUT/motion caches once per MCP request, retaining the GPU and pipelines and preserving decoder continuity within a streamed sequence. The existing end-to-end equality assertion is retained; diagnostics no longer dump entire PNG/base64 arrays. Root owns the green rerun.

Lifecycle follow-up: the complete MCP integration suite initially passed its assertions while printing `double free or corruption (out)`. `TokioChildProcess::new` in rmcp 3.5.1 overrides `Command.stderr(Stdio::null())` with inherited stderr, and its transport cleanup does not surface the subprocess's final exit status. A direct JSON-RPC lifecycle harness (`artifacts/mcp-productivity/probe_shutdown.py`) subsequently reproduced real SIGSEGV exits after successful tool replies in frame-only and frame+export variants; export-only exited normally. Root's process trace identifies process 444453 as `neptune-video-mcp` and faulting thread 444455 as its second spawned thread, the frames worker. The worker was detached, so dropping the final request sender started GPU destruction while `neptune-video-mcp` immediately entered `std::process::exit` and C-library exit handlers. This teardown race is the supported diagnosis; no C-library backtrace was captured. A batch-gdb frame-only run changed timing and exited normally, retained under `artifacts/mcp-productivity/lifecycle-gdb`.

The frames lane now owns its worker handle. MCP shutdown cancels queued/active work and the lane's own source decoders, then joins the frames worker before returning to `main`. GPU state therefore finishes dropping before C-library process exit. Bounded stream delivery checks cancellation while full. The idle worker blocks without polling; shutdown drops the lane’s sole sender to wake it while cloned handles remain alive. This shutdown runs only in the headless server. A pure unit checks idempotent shutdown and refusal through all clones; root owns the standing native subprocess-exit regression and rebuilt-binary red/green matrix. Do not treat earlier green tool assertions as a clean native subprocess exit.

The initial joined-frame fix exposed the same independent race in the encoded-export queue: after removing incidental 100 ms shutdown polling, the final native matrix passed frame and combined cases but export-only still exited with SIGSEGV in two trials. `RenderQueue::shutdown` deliberately returns after its cancellation grace and does not join its GPU-owning thread. The queue now retains that thread handle and offers an explicit `shutdown_and_join` for headless shutdown. MCP calls it before process exit; the interactive window retains its existing bounded shutdown/Drop behavior. A pure regression asserts the runner's resources have been destroyed before headless shutdown returns. Native final matrix acceptance remains root-owned and must use the rebuilt final source; earlier passing matrices are not acceptance for the later source.
